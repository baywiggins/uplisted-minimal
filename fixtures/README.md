# Synthetic fixture inputs

These examples are development inputs, not live RentCast captures or benchmark results. Never send the synthetic address to live RentCast or another live property-data provider. Sending synthetic task inputs to the explicitly enabled real model is expected during model evaluation. `property-case.json` is seed input: `init-demo` computes revision, hash and provenance rather than trusting caller-supplied hashes. `rentcast-evidence.json` is an internal normalized fixture input, **not** a claim to match every field of RentCast’s raw HTTP schema. Stage 05 maps it through the fixture adapter; Stage 13 adds separately reviewed provider-shaped raw HTTP fixtures from current official documentation. `floorplan-intent.json` is a valid semantic example with unknown measurements.

Use the fixed clock `2026-11-07T12:00:00Z` in deterministic tests. An ordinary local demo uses a domain clock explicitly shown as a synthetic replay clock in fixture mode, so example freshness is reproducible. Keep actual UTC audit timestamps and monotonic execution deadlines separate. A real model can use frozen domain time with fixture evidence; live RentCast freshness must use actual UTC. The UI labels both model mode and evidence mode. Human-confirmed live property data must use a new non-synthetic case and actual UTC time.

No example includes a credential, real client record, or measured property geometry. Stage 02 adds explicit malformed fixtures alongside these positives; Stage 12 maps public scenario specifications to executable, independently reviewed drivers and assertions.
